# SolRPDS 기반 러그풀 탐지 — 제대로 된 실험 결과

> 이전 실험의 두 치명적 약점(라벨 약함 · 출처편향)을 해결하기 위해, 온체인으로 검증된
> 공개 데이터셋 **SolRPDS**(Alhaidari et al., CODASPY '25, Flipside 36억 tx 기반)를 직접 사용.
> 코드: [`../code/ml_solrpds.py`](../code/ml_solrpds.py) · 원자료: `raw/solrpds/{2021..2024}.csv` · 로그: [`../data/solrpds_result.txt`](../data/solrpds_result.txt)

## 왜 이 데이터인가 — 이전 실험의 두 문제를 정면으로 해결

| 문제 | 이전(RugCheck vs Jupiter) | SolRPDS |
|---|---|---|
| **라벨 약함** | RugCheck `rugged=1`이 1500개 중 **0개** → 라벨이 "러그 확정"이 아니라 "스캠 의심" | 라벨 = `INACTIVITY_STATUS`. 유동성 제거 후 스왑 중단 = 온체인 파생 라벨 (벤더 점수 아님) |
| **출처편향** | 러그=RugCheck / 정상=Jupiter → 서로 다른 집단, 단일 feature AUC 0.93 | 러그(Inactive)·정상(Active) 모두 **같은 Flipside 추출**에서 나온 동일 집단 → 출처 인공물 없음 |

- 총 **116,304개 풀** · Inactive(러그의심) 22,555 (19.4%) / Active 93,749 (80.6%)
- feature(누수 없는 것만): 추가/제거 유동성 총량(`add`,`rem`), 추가/제거 횟수(`na`,`nr`), add/remove 비율(`ratio`), 수명(`life`=마지막−첫 활동), 제거/추가 비율(`rem_to_add`)
- **의도적으로 절대 타임스탬프를 feature에서 제외** (논문 0.94의 누수 원인으로 의심 — 아래 참조)

## 결과

### 프로토콜 A — 논문 재현 (2022 train → 2021 test, 교차연도)

| 모델 | AUC | F1 | MCC | 논문 MCC |
|---|---|---|---|---|
| AdaBoost | 0.796 | 0.220 | **0.176** | 0.942 |
| XGBoost | 0.813 | 0.253 | **0.226** | (RF 0.935) |
| LogReg | 0.836 | 0.238 | **0.250** | 0.728 |
| MLP(NN) | 0.797 | 0.278 | **0.236** | 0.735 |
| kNN | 0.744 | 0.187 | 0.135 | 0.181 |

**우리 교차연도 MCC는 0.12~0.25로, 논문의 0.73~0.94보다 크게 낮다.**

### 프로토콜 B — robust 5-fold CV (동일분포, 전체 11.6만)

| 모델 | AUC | F1 | MCC | AUCPRC |
|---|---|---|---|---|
| **GradientBoosting** | 0.897 | 0.619 | **0.553** | 0.695 |
| **XGBoost** | 0.901 | 0.641 | **0.552** | 0.710 |
| AdaBoost | 0.889 | 0.576 | 0.516 | 0.672 |

**동일분포에서 현실적 성능 = MCC ~0.55, AUC ~0.90.** 트리 부스팅이 최상.

### 프로토콜 B-2 — 스케일링 비교 (스케일 민감 모델, 층화 16k)

| 모델 | none | Standard | MinMax |
|---|---|---|---|
| LogReg (MCC) | 0.511 | 0.511 | 0.509 |
| **SVM(RBF) (MCC)** | **0.083** | **0.531** | 0.525 |
| MLP(NN) (MCC) | 0.482 | **0.558** | 0.526 |

**스케일링이 필수임을 결정적으로 입증** — SVM(RBF)은 정규화 없이 MCC 0.083(거의 무용)
→ Standard 후 0.531로 **6배**. MLP도 +0.076. (트리는 스케일 무관하여 정규화 불필요.)

### 순환성 검증 — 제거횟수(`nr`, 라벨 정의의 일부) 제거 시

| | MCC | AUC |
|---|---|---|
| 전체 feature | 0.552 | 0.901 |
| `nr` 제거 | 0.532 | 0.895 |
| 차이 | **0.019** | 0.006 |

**제거횟수를 빼도 성능이 거의 유지** → 라벨을 그냥 되읽는 순환이 아니라 실제 신호가 존재.

### Feature 중요도 (permutation) & 러그 vs 정상 원값 median

| `add` 추가유동성 | 0.087 | 4.26M | 9.9k | 러그가 미끼로 더 많이 넣음 |

## 결론 (팩트)

1. **두 문제는 이 데이터로 해결됨.** 라벨은 온체인 검증, 러그·정상은 동일 집단 → 이전의
   "라벨 약함 + 출처편향"이 구조적으로 사라짐.

2. **정직한 현실 성능 = MCC 0.55 / AUC 0.90 / AUCPRC 0.71** (동일분포). 논문의 0.94가 아니다.

3. **논문 0.94는 타임스탬프 누수로 부풀려졌을 가능성이 높다.** 논문은 교차연도(2022→2021)로
   0.94를 보고했으나, 동일 프로토콜을 누수 없는 feature로 재현하면 0.18에 그친다. 절대
   타임스탬프(`LAST_SWAP`/`LAST_ACTIVITY`)는 cutoff(2024-11-01) 대비 inactivity를 직접
   인코딩하므로, 이를 feature로 넣으면 라벨을 거의 그대로 읽게 된다. 우리는 수명(last−first)만
   써서 이를 배제했고, 그 결과가 더 방어 가능한 상한(~0.55)이다.

4. **교차연도 일반화는 원래 어렵다 (0.18).** 2021년은 pump.fun 이전(Raydium 시대)으로 2022년과
   레짐이 다르다. 배포형 탐지기의 실제 한계 — 시대가 바뀌면 성능이 급락한다.

5. **스케일링/정규화는 스케일 민감 모델에 필수** (SVM 0.083→0.531). 트리 부스팅은 정규화 없이도
   최상(0.55)이라 실무적으로 가장 견고한 선택.

6. **솔라나 러그의 온체인 지문**: 미끼 유동성 대량 투입(add↑) → 더 큰 규모로 회수(rem↑↑,
   ratio<1, rem_to_add>1) → **적은 거래로 ~16시간 만에 사망**. 해석 가능하고 재현 가능한 특징.
